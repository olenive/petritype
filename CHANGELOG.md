# Changelog

## 0.5.0, 2026-11-23

The [`v0.5.0` tag](https://github.com/olenive/petritype/tree/v0.5.0). A minor version, since closed nets can break a program: the entry marked as such says what a program changes. It carries the nineteen shared transcripts.

- `PROTOCOL.md` §3 says that a client keeps an error code it does not know as written and treats the response as a failed request with that code. The Python runner reads no error answers, so nothing in it changed; the Rust runner's `protocol` types now keep such a code (`ErrorCode::Other`).
- A keyed edge can choose its token by another input of the same firing. `Clause(key, input=place, input_key=key)` in the filter of a `TakeWhereEdge` or `MutateWhereEdge` compares the edge's token's `key` with the key `input_key` of the token the transition gets from `place` (a place's name or a `Port` pair): `MutateWhereEdge("Couriers", "Load", "courier", where=Filter((Clause("name", input="Orders", input_key="courier"),)))` hands the body the courier the order names. Such an edge is a bound edge and the input it names its source. For each source, the oldest source token that has a match fires, with the oldest match for it; a source token with no match waits where it is and does not hold back those behind it, and every other token keeps its place and its id. Several edges may be bound to one source, a take-where source considers only its own matches, a constant or parameter clause may stand beside the input clause, and a failed firing that restores puts both tokens back at the front with their ids. `KeyedEdges.pairing` finds the pair with one pass over each bound place and a lookup per source token tried. Outside a firing the clause accepts nothing (`Clause.accepts`, `Filter.keeps`, `Query.matches`, `Query.first`). The build refuses a bound edge whose source the transition does not read, whose source's edge gives every token (a drain, a survey, or an argument annotated `list[T]`) or is bound itself, whose clauses name two sources, or whose keys either place does not declare, and a source or bound place that the transition reads through a second edge; each message names the transition and the places.
- The concurrent runtime hands a launch the net's parameters, so a keyed edge whose filter names a net parameter fires there as it does sequentially; until now its launch read no parameters and failed for want of a match.
- The protocol runner writes an input clause in a topology as declared, `{"key": "name", "input": {"place": "Orders", "key": "courier"}}` (with `port` beside `place` for a port), and answers a `query` or `set_filter` whose filter holds one with `invalid_params`, saying why. The protocol stays version 2: the clause is a new shape shown as declared (PROTOCOL.md §5.1, §10, §13.2, §13.5). A new shared transcript, `tests/protocol/16_keyed_by_input.json`, over the conformance net `couriers` (`tests/protocol_nets/couriers.py`, PROTOCOL.md §11): the mutate and the take form, an order whose courier is not there passed over and kept with its id, a client's filter with the clause refused, and a failed firing that puts back the call and the courier. It is replayed over pipes too, and every other transcript re-records to the same bytes. The recorder names a token whose object has no `name`, `kind` or `id` by its first text field.
- The Graphviz drawing writes a keyed edge's filter on the edge, as petritype-dot does: `class in {Bird}`, `class = $season`, `name = Orders.courier` (`name = Level 1/Lobby.courier` for a port), joined by `and`, and `any` for a filter with no clauses. This changes the drawing of every net with a keyed edge, the wildlife example's among them, which until now drew a keyed edge like a plain one.
- `PROTOCOL.md` calls the edges that leave their token in its place (`snapshot`, `survey`, `mutate`, `mutate_where`) non-consuming edges, where it called them read edges: a mutate edge changes its token, so the old name misled, and "read" now names the read edges below. Nothing on the wire changed for the rename. The README, `PROPOSED_DESIGN_GOALS.md`, the docstrings, the comments and the build's messages say non-consuming edges where they said read edges or read arcs for that group; the engine's `transition_names_to_read_edges` and `MapTransitionNames.to_read_edges` keep their names and map each transition to all its non-consuming edges.
- Three input edges hand the body tokens to look at, live, without taking or copying them, the **read edges**: `ReadEdge(place, transition, argument)` the front token and `ReadWhereEdge(place, transition, argument, where=Filter(...))` the oldest token the filter keeps, each holding its transition back while there is none, and `ReadAllEdge(place, transition, argument)` every token, oldest first, as a list of the body's own, possibly empty, never holding it back. A `ReadAllEdge` argument is annotated `list[T]` and a `ReadEdge` or `ReadWhereEdge` argument as the place's type, each checked when the graph is built. No token moves, no id changes, nothing is copied and no event tells of the tokens read, so a token that carries a net keeps its net and the net its `net_id`. The body is handed the live token: leaving it unchanged is the author's promise, which Python cannot enforce, and a change shows in the place with nothing telling of it. A `SnapshotEdge` of a token that carries a net still copies the net under a new `net_id`: to look at such a token, use a read edge. A net keeps them in `ExecutableGraph.read_edges` (`construct_graph` sorts them there), and `ReadWhereEdge` is re-exported from `petritype.core.keys`. A read or read-where edge may be the source of a bound edge, a read-where edge may be bound itself, and they work on a port of a subnet place. The build refuses a read-all edge as a source, and a place a read edge reads that another input edge of the same transition names, of any kind; the message names the transition and the place. The concurrent runtime keeps inner firings out of the nets of the tokens a body in flight reads, as it does for those it mutates (`FiringTokenIds.read`).
- The protocol runner writes the read edges in a topology as `kind: "read"`, `"read_where"` (with its `filter`, as declared) and `"read_all"`, and reports a firing with one as it reports any firing, in two pieces, naming in `consumed` only what it took and writing no `mutated` for what it read. The protocol stays version 2: the kinds are new optional values, which an older reader draws as plain edges (PROTOCOL.md §5.1, §6.3, §10, §13.5). `PROTOCOL.md` says that a reader keeps an edge whose kind or whose clause it does not know and reads the rest of the topology (§5.1). `petritype.runner.protocol.Edge.kind` now reads any string, the kinds the runner writes being `EDGE_KINDS`, so a topology with an edge kind or a clause this version does not know is read whole, each kept as it came; until now `Edge` refused a kind it did not know. A reader built on the `protocol` types of petritype-runner 0.2.x (Rust) cannot read a topology that uses the input clause or a read kind, nor one built on this library's wire types up to 0.4.1 a topology that uses a read kind.
- A new shared transcript, `tests/protocol/17_read_edges.json`, over the conformance net `roll-call` (`tests/protocol_nets/roll_call.py`, PROTOCOL.md §11): a roll call that reads squads, each a net built from the registered template `Squad`, with a `read_all`, a `read` and a bound `read_where` edge; the squads keep their token ids and their nets' nested ids, and no line tells of them. It is replayed over pipes too, and every other transcript re-records to the same bytes.
- The Graphviz drawing draws a read edge as a dotted dim grey arrow towards the transition, told apart from a snapshot's dashed one: a read-where edge with its filter written on it, a read-all edge with a hollow arrowhead and the label `*`. It turns magenta when its transition fires, as the other non-consuming edges do. `RustworkxReadEdgeData` gains `read` and `read_all`, and `RustworkxGraph.read_edges_to_transitions` takes `read_edges`.
- The protocol runner writes `port: true` on the port places of every net's topology, the loaded net's and a token's net's as well as a subnet's; until now only a subnet's own topology showed them, and a net that was no subnet showed none, whatever its definition marked (PROTOCOL.md §5.1, §12.7). A place of net-carrying tokens says nothing of the ports its tokens' nets offer, since those nets arrive in tokens as the net runs: each token's net shows its own when read by path or nested id. `Topologies.of` loses its `subnet` argument. The Graphviz drawing already gave a port a second ring in the drawing of its own net, whichever net that is, and still does. Every shared transcript re-records to the same bytes.
- An input edge on a place whose tokens carry nets may name the ports its body reaches in those tokens' nets: `reaches`, a tuple of names given by keyword alone on every input edge class, `MutateEdge("Field", "Hand Over", "unit", reaches=("Orders In",))`. It is a declaration for readers and drawings, as a group is, and changes nothing about firing. The build refuses it on a place that holds no nets (a port of a subnet place counting by the port's own `nested`) and refuses an empty name, naming the transition and the place (`ExecutableGraphCheck.ensure_reaches_are_sound`). Whether a token's net has the ports named is checked neither when the net is built nor when the edge fires; which places of the net a body may write is the rule on closed nets, below. An output edge has no `reaches`. A field named in `PositionalArgsBaseModel._keyword_only` is given by keyword alone, so a keyed edge's filter stays its fourth positional argument.
- The protocol runner writes an input edge's `reaches` in a topology after its `filter`, in the order declared, and leaves it out when empty: `{"place": "Field", "transition": "Hand Over", "direction": "in", "kind": "mutate", "reaches": ["Orders In"]}`. The protocol stays version 2: `reaches` is a new optional field (PROTOCOL.md §5.1, §10, §12.7). `petritype.runner.protocol.Edge` gains `reaches`, and the models a topology is read into (`Topology`, `Place`, `SubnetPlace`, `PlaceStyle`, `Transition`, `Edge` and `Control`, now on the base `Tolerant`) keep a field they do not know as it came and read the rest, where until now such a field refused the whole topology; every other wire model still refuses one. A reader built on this library's wire types up to and including 0.4.1 cannot read a topology that carries `reaches`; one built on the `protocol` types of petritype-runner 0.2.x (Rust), which ignore a field they do not know, reads the rest of it and drops `reaches`.
- A new shared transcript, `tests/protocol/18_ports_on_a_token.json`, over the conformance net `trays` (`tests/protocol_nets/trays.py`, PROTOCOL.md §11): a unit, a net built from the registered template `Unit` with two ports, `Orders In` and `Shots Out`, carried by a token; its own topology read by path showing `port` on both; and two outer mutate edges that declare the port each reaches, one handing the unit an order and one collecting its shot into `Reports`. It is replayed over pipes too, and every other transcript re-records to the same bytes.
- The Graphviz drawing writes the ports an edge reaches as its label's last line, `reaches Orders In, Shots Out`, after a keyed edge's filter or a read-all's `*`, as petritype-dot does. `RustworkxArgumentEdgeData` and `RustworkxReadEdgeData` gain `reaches`, and `NodeLabel.edge_label` writes an edge's label. A snapshot or survey edge, which had no label, has one when it declares `reaches`.
- `PROTOCOL.md` says what a connection's filter is, with nothing on the wire changed and the protocol still version 2: a view a client chooses for itself, to be sent less, which any client may set, change or clear, so a host that must keep some tokens from some clients enforces that itself, in front of the net process (§9.2, §13.4). `distinct` reads every token whatever the filter by design (§13.3), and takes `places` in place of a filter, as §12.7 now says; `get_log` returns the same entries whatever the filter, in both runners, since the log is the net's own record (§8, §13.4); and both runners send the `nested` notifications of a net that a hidden token carries whole, since each inner net has its own filter (§13.4).
- **A change that can break a program: a net that marks a port is closed.** A net whose definition marks at least one place as a port (`ListPlaceNode(..., port=True)`) is closed unless it declares itself open: from outside it, tokens are put, taken and replaced only at its ports. Outside a net are a body, guard or key function of a transition of the net around it, by any edge; the program and its drivers; and the runner's requests. Inside are its own transitions, the controls it declares, the tokens its definition starts it with and the engine's own moves (a firing's inputs and outputs, a failed firing's restore, a deep step). A write from outside at a place that is not a port raises `ClosedNetError` (a `ValueError`) from `NestedNets.put` and `NestedNets.take`, and from the runtime's `Extend` and `SetTokens`, which a strict `RunContext` raises and any other drops and logs, as it does any command the net cannot take. A write at `Port(subnet place, port)` is a write to a place of the net around the subnet: a closed net refuses it from outside, since a port of a subnet place is never one of its own ports, and an open one lets it land. A body that writes so fails its firing with the error as the `TransitionFailedError`'s cause, at the cost of any failure: the tokens it took, unless `restore_tokens_on_failure` puts them back, and what it did before the refusal stays done. A body that catches the error fails all the same. The error names the net (its template, or `#` and its `net_id`), the place and the act, and says how to put it right. **Three ways to make a refused write land:** mark the place as a port; start the net with the token in its definition, as a seed or a template's token; or declare the net open, `construct_graph(..., open=True)`, read as `graph.open`. `graph.is_closed` tells whether a net is closed. A net that marks no port is open, as before.
- A body of the net around a net that marks a port, while it holds the net, may not set its parameters (`NetParams.set`, `NestedNets.set_param`), its switches or a transition's keywords, nor fire it by name or with a selector of its own: each raises `HeldByBodyError` (a `ValueError`) and fails the firing, on a closed net and on one declared open alike, since `open` opens the places and not the knobs. A held net that marks no port keeps them for a body, as before, so the transit example's `Depart` and `Arrive` still set their cabin's `stopped`. The program, its drivers and the runner keep the knobs and firing by name on every net. Reading, stepping (a body may step a net it holds) and the whole-state acts (`import_marking`, `NetJson.load_into` and `restore`, `NestedNets.fork`, saving) stay allowed. `NestedNets.subnet_scope` on a net a body holds holds the subnet too for the block's time. A command a control of the net gives (`apply_control`, the protocol runner's `press`) is inside the net and lands at any place; `petritype.runtime.by_control` marks one so.
- Python can enforce the rule only through its own functions, the runtime's commands and the runner, and for a body by a check when it returns: stage 1 records the tokens and ids of each private place of every closed net a body is handed live (by every edge kind but a snapshot or a survey, which hand over copies), and the knobs of every net it is handed that marks a port, and the firing fails if they differ when the body returns. A step of the net's own that the body makes counts as the net's. A change inside a token object where it lies, or inside a parameter's value, goes unseen, and **a program that edits a place's list, `params` or `disabled` directly is not caught.** `ExecutableGraph.held_by_body`, `ClosedNets`, `BodyHold` and `FiringTokenIds.held` are the pieces; `CLOSED_WITHOUT_PORTS`, `False`, is the one default that stage two, which will close every net that does not declare itself open, turns to `True`.
- The protocol runner's `inject`, at the top level, by a port pair and by path, answers the new error code `closed_net` at a place of a closed net that is not one of its ports, and adds nothing; a `press` lands where its control puts the token. A net that declares itself open shows `open: true` in its own topology and any other net shows no `open`, so a reader knows a net is closed when it shows a `port` and no `open`; `petritype.runner.protocol.Topology` gains `open`. The protocol stays version 2: `open` is a new optional field and `closed_net` a new error code (PROTOCOL.md §3, §5.1, §6.4, §10, §12.7). A reader built on this library's wire types up to and including 0.4.1 cannot read a topology that carries `open`; one built on the `protocol` types of petritype-runner 0.2.x (Rust) reads the rest of it and drops `open`.
- A new shared transcript, `tests/protocol/19_closed_nets.json`, over the conformance net `post-office` (`tests/protocol_nets/post_office.py`, PROTOCOL.md §11): a closed post and an open one, each a net built from a registered template carried by a token; a body that puts a letter at the closed post's port and lands; three `inject`s by path, at that port, at its other place, refused with `closed_net`, and at the open post's same place, which lands; and a body that writes a forgery into the closed post's other place and fails, losing what it took, since the net restores nothing. It is replayed over pipes too, and every other transcript re-records to the same bytes.
- The README's "Closed nets" section says how to tell a net is closed and how to make a refused write land, for a program written before this change.

## 0.4.0, 2026-11-22

The [`v0.4.0` tag](https://github.com/olenive/petritype/tree/v0.4.0).

- The protocol runner serves groups (PROTOCOL.md §5.1): a net's topology lists its groups as `groups`, in their order, and the `group` of each place, subnet place and transition in one, each left out when absent, for the loaded net and every inner net, each its own; a port listed in a subnet place's `ports` carries no `group`, its group being the subnet's. Nothing else on the wire changes, and the protocol stays version 2. A new shared transcript, `tests/protocol/11_groups.json`, over the conformance net `groups`; every other transcript re-records to the same bytes.
- Groups: `group=` on `ListPlaceNode`, `SubnetPlaceNode` and `FunctionTransitionNode` names the group the node is in, a label on parts of one net that only drawings read. `ExecutableGraph.groups` lists a net's groups in the order of their first mention, the places read before the transitions. A node is in one group or none, a name may hold any character, and a subnet or a net a token carries has groups of its own. Groups change nothing about how a net runs: it fires, steps, numbers its tokens, records its events and saves exactly as it would with none, and a saved net never mentions them; a copy or a template carries them. The Graphviz drawing frames each group as a dashed cluster titled with its name, in order (`RustworkxToGraphviz.dot_source` and `draw`, which `SimpleGraphvizVisualization` now draws through); a net with no groups draws the source it drew before. The example `examples/groups/hike.py`, with its notebook.
- The protocol runner serves subnet places (PROTOCOL.md §12.7). A subnet is one more inner net, addressed by a path whose step is the subnet place alone, `[{"place": "Level 1"}]`, or by its `nested_id`, known from `load` or `reset` with its own version, topology, progress, log view and `fireable` baseline. The net around it lists a subnet place with its template as `type_name`, its `ports` and its `stepping`, names a port with `port` beside `place` in its edges, `added`, `removed`, `mutated`, `hidden`, `get_place_tokens`, `inject` and `query`'s matches, and as `{"place", "port"}` in `consumed`, `produced` and the log; its marking gives a subnet place's entry as `{subnet, ports}`, and in the subnet's own topology a port place carries `port: true`. A change of a port place raises the versions of both nets that see it, and the notification carries the other's as `subnet_marking_versions` or `outer_marking_version`; both nets' `fireable` sets are compared after it. A read of a subnet waits while a firing of the net around it on one of its ports is in flight, and a read of the net around a subnet while a firing of the subnet on its port is in flight is answered from the port as that firing left it. `Filter.keeps` takes the key a net names a place by, so that a filter restricted to a `Port` matches it, a keyed edge on a port included. The levels example is served as `levels-world`. A new shared transcript, `tests/protocol/09_subnet_places.json`, over the conformance net `levels`; the harness folds the versions across a port and the recorder masks them.
- Subnet places: `SubnetPlaceNode(name, graph, stepping="inner_first")` holds a net of its own, its subnet, for the whole life of the net around it, which reaches it only through the places the subnet marks `ListPlaceNode(..., port=True)`. An edge names a port by the pair `Port("Level 1", "Lobby")` where it would name a place, and every input edge kind, every way of choosing an output, guards, keyed edges, `Query` and `Extend`/`SetTokens` then use it as a place of the outer net. A port keeps one list of tokens and one set of ids, the subnet's, whichever net looks. A change is told once, by the net through which it was made: the outer net's events name a port by its pair (`Fired`, `Failed`, `Added`, `Removed` and `Mutated` take a `PlaceKey`), and the subnet's are lifted as `Nested` under `PathStep("Level 1")`, a step with no token. A subnet steps as one net at its place's position under its place's rule, takes no turn while an outer firing on one of its ports is in flight, and is read with `graph.subnet(name)` and stepped or changed by the program inside `NestedNets.subnet_scope`, which raises `SubnetHeldError` meanwhile. `NetJson` saves a subnet built through a template inside its place's entry, a list of one saved form, and refuses one built without, naming the place. The Graphviz drawing shows a subnet place as one rounded box with a cell per port, its name and count, an edge ending at its port's cell, and a port with a second ring in the subnet's own drawing. The build refuses a port the subnet does not have, an edge whose type does not fit its port, an edge on a subnet place, a `Port` beside a place that is not a subnet place, a subnet place marked as a port and one net in two subnet places. `PathStep`'s `token` and `net` default to `None` for a subnet step, and an unknown place in an edge is now a `ValueError` naming it rather than a `KeyError`. The example `examples/subnet_places/levels.py`, with its notebook.
- The protocol runner speaks version 2 of the net protocol (PROTOCOL.md §10). An inner net's `path` is a list of steps from the loaded net down, `{"place", "token", "net"}` for a net carried by a token, in requests, results, a token's `nets`, the `nested` notification, the `step` result and the log, so a place or a net may be named with any character and still be addressed. A path of any other shape is `invalid_params`, and one that names no live net is `unknown_net`, naming the step that failed by its index from 0. A net's progress counts only the firings of its own transitions: the loaded net's `fired_counts` no longer holds a joined name for each firing inside its tokens. The shared transcripts are re-recorded for version 2, and the transcript recorder keeps the names and masks of a transcript it re-records.
- A stepping rule per place that holds nets, `ListPlaceNode(..., nested=True, stepping=...)`: `"inner_first"`, the default, fires the place's nets until they are at rest before the net around them; `"take_turns"` has them fire in turn with it; `"outer_first"` lets them fire only when it and its turn-takers have nothing to fire; `"passive"` leaves them to a body or the program. One deep step tries the inner-first nets, then the ring of the net and its take-turns nets from after the one that fired last, then the outer-first nets, and a net's turn is a deep step of its own, so every level follows the rules of its own places (PROTOCOL.md §12.3). The sequential and concurrent runtimes and the protocol runner step that way, and the runner's topology carries each such place's `stepping`. **Removed:** `construct_graph(deep_policy=...)`, `ExecutableGraph.deep_policy` and `ListPlaceNode(..., passive=True)`; a net that relied on the old default states `stepping="outer_first"` on its places, as the transit example does. A path inside the library is a tuple of `PathStep(place, token, net)` values, and a firing inside an inner net is an `InnerFiring(path, transition)`, which `fire_one_transition` returns and `fired_counts`, `last_fired` and `RunSummary.fired` count it under, where they held a name joined with `/`. The concurrent runtime now fires an inner net beside outer bodies in flight, except the nets of a token such a body holds, and the sequential fuse counts the inner nets a deep step would enter. A new shared transcript, `tests/protocol/10_stepping_rules.json`, over the conformance net `stepping-rules`.

## 0.3.0, 2026-10-17

The [`v0.3.0` tag](https://github.com/olenive/petritype/tree/v0.3.0).

- Nets as tokens: a `nested=True` place holds tokens that carry Petri nets of their own, which the outer net runs, logs and reaches inside, and a net saves and restores as JSON through a registered template (PROTOCOL.md §12).
- Token keys, queries and filters: places derive keys from their tokens, `Filter` and `Query` select by them (`Query.distinct` lists a key's values), `TakeWhereEdge` and `MutateWhereEdge` act on matching tokens only, and the protocol runner answers `query`, `distinct` and `set_filter` (PROTOCOL.md §13).
- `DrainEdge` and `SurveyEdge`, input edges that accept an empty place: a drain takes every token and a survey copies every token, zero or more either way.
- Marimo notebooks for the transit journey, the wildlife filter, the shop day, the traffic light junction and the rooms state machine.
- The traffic light (`examples/edges_on_empty_places/traffic_light.py`), a drain beside a plain read, with its shared transcript `tests/protocol/08_traffic_light.json`.
- Net-declared controls and place styles, `@petri_net(controls=..., place_styles=...)`, served as `topology.controls` and `places[].style`; the protocol's `press` runs a control, and the `Fire` command fires a named transition if it is fireable.
- A subclass of a JSON scalar, such as `class Colour(str)`, is serializable with its scalar's JSON form.
